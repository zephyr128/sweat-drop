# Plan: BLE Machine Identity — Name + Serial Number Architecture (Vortex Pilot Critical Fix)

**Created:** 2026-05-08 21:55
**Author:** architect
**Severity:** **P0 — CRITICAL ARCHITECTURAL FIX**
**Pilot impact:** Currently broken — strict identity matching by `sensor_id` (Web Bluetooth opaque hash) cannot match BLE peripheral on iOS because Apple deliberately hides MAC address. Pilot users blocked from training. Cross-talk reverts to occurring if we relax matching — both unacceptable.
**Goal:** Replace per-origin Web Bluetooth `device.id` with cross-device-stable BLE Local Name + DIS Serial Number identity. No hotfixes. No cross-talk. No re-pairing storm.

---

## Context

### Why we're here

The original BLE pairing architecture stored Chrome Web Bluetooth `device.id` (an opaque per-origin hash like `ZdvQdqpyKIAdzCfNjdKP/Q==`) as `machines.sensor_id`. The mobile client was supposed to "match by name" per the comment in `apps/admin-panel/components/modules/MachinesManager.tsx:351`, but the actual mobile implementation in `apps/mobile-app/lib/ble-service.ts:448-491` silently fell back to **strongest-RSSI** without identity verification. This:

- **Worked accidentally** in 90% of cases because the user's machine emits the strongest BLE signal when they're standing on it
- **Caused deterministic cross-talk** in the remaining 10% (target machine off, neighbor on) — explaining the 305 fraud events on 2 Vortex pilot users (`unlock_machine_lock_mismatch`, `heartbeat_without_lock`, `rpm_without_lock`, `machine_lock_starvation`)
- **Was discovered** when Step 1 of `bugfix_pause_auto_resume_and_ble_machine_crosstalk_vortex_production.md` enforced strict identity matching, exposing the architectural flaw

### The fundamental constraint

iOS by design (CoreBluetooth) does not expose BLE MAC addresses. `CBPeripheral.identifier` is a per-(iOS device × app installation) UUID, not the actual hardware identifier. **The Web Bluetooth `device.id` saved during admin pairing is similarly per-origin** and cannot be reproduced on a different device or browser.

### The right identifier

The BLE specification defines two cross-device-stable identifiers:

1. **Local Name** in advertisement packet (`device.name`) — set by FTMS firmware, broadcast on every advertising interval, **identical on every scanning device** regardless of platform. Example from current Vortex incident: `38069-129`.

2. **Device Information Service Serial Number** (DIS, UUID `0x180A`, characteristic `0x2A25`) — read after GATT connection, **hardware-bound, immutable**, set at factory burn-in.

This plan rebuilds machine identity around these two BLE-native fields. The legacy `sensor_id` column stays for backward compatibility but is deprecated and no longer authoritative.

### What this plan does NOT do (out of scope)

- ❌ Force re-pairing of every machine (auto-backfill handles legacy machines on first successful connection)
- ❌ Change FTMS protocol parsing (`ble-ftms.ts` untouched)
- ❌ Address pause auto-resume bug (covered separately in `bugfix_pause_auto_resume_and_ble_machine_crosstalk_vortex_production.md` Step 2)
- ❌ Address Android Foreground Service for background BLE (covered in `vortex_pilot_hardening_workout_flow_critical_fixes.md` Step 3)
- ❌ Yesoul proprietary protocol (Vortex has none; Yesoul peripherals use different naming convention, treated separately if it ever becomes relevant)

```sql
COMMENT ON COLUMN public.machines.ble_pairing_verified IS
  'TRUE once a workout has successfully read DIS Serial Number from this machine. '

-- Index for the per-gym name uniqueness check + scan-result filter
CREATE INDEX IF NOT EXISTS idx_machines_gym_ble_device_name
  ON public.machines(gym_id, ble_device_name)
  WHERE ble_device_name IS NOT NULL;

-- Per-gym uniqueness constraint (factory-defect catcher)
-- Enforced via trigger rather than UNIQUE because legacy NULL ble_device_name rows
-- must be allowed during the rollout window.
CREATE OR REPLACE FUNCTION public.machines_ble_device_name_unique_per_gym_check()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
  IF NEW.ble_device_name IS NULL THEN
    RETURN NEW;
  END IF;
  IF EXISTS (
    SELECT 1 FROM public.machines
    WHERE gym_id = NEW.gym_id
      AND ble_device_name = NEW.ble_device_name
      AND id <> NEW.id
  ) THEN
    RAISE EXCEPTION
      'BLE device name % already used by another machine in gym %. '
      'Possible factory-defect duplicate broadcast name. Contact equipment vendor.',
      NEW.ble_device_name, NEW.gym_id;
  END IF;
  RETURN NEW;
END;
$$;

DROP TRIGGER IF EXISTS trg_machines_ble_device_name_unique ON public.machines;
CREATE TRIGGER trg_machines_ble_device_name_unique
  BEFORE INSERT OR UPDATE OF ble_device_name, gym_id ON public.machines
  FOR EACH ROW
  EXECUTE FUNCTION public.machines_ble_device_name_unique_per_gym_check();
```

#### Auto-backfill RPC

```sql
-- Called by mobile client on first successful BLE connection to a machine.
-- Caches the observed Local Name + DIS Serial Number into machines row.
-- Idempotent: subsequent calls are no-ops if values already set.
-- Security: caller must be the current_user_id holding the machine lock.
CREATE OR REPLACE FUNCTION public.cache_machine_ble_identity(
  p_machine_id      UUID,
  p_observed_name   TEXT,
  p_observed_serial TEXT
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  v_machine RECORD;
  v_action  TEXT := 'no_change';
  v_changes JSONB := '{}'::jsonb;
BEGIN
  IF auth.uid() IS NULL THEN
    RAISE EXCEPTION 'Unauthorized';
  END IF;

  SELECT id, gym_id, current_user_id, is_busy, ble_device_name, ble_serial_number, ble_pairing_verified
  INTO v_machine
  FROM public.machines
  WHERE id = p_machine_id
  FOR UPDATE;

  IF NOT FOUND THEN
    RAISE EXCEPTION 'Machine not found: %', p_machine_id;
  END IF;

  -- Anti-spoofing: only the user currently locking the machine can backfill its identity
  IF NOT v_machine.is_busy OR v_machine.current_user_id IS DISTINCT FROM auth.uid() THEN
    PERFORM public.log_fraud_event(
      auth.uid(), v_machine.gym_id, 'cache_ble_identity_unauthorized', 'high',
      jsonb_build_object('machine_id', p_machine_id, 'is_busy', v_machine.is_busy));
    RAISE EXCEPTION 'Caller does not hold lock on this machine';
  END IF;

  -- Verification path: identity already cached → must match exactly
  IF v_machine.ble_pairing_verified AND v_machine.ble_serial_number IS NOT NULL THEN
    IF p_observed_serial IS DISTINCT FROM v_machine.ble_serial_number
       OR (v_machine.ble_device_name IS NOT NULL AND p_observed_name IS DISTINCT FROM v_machine.ble_device_name)
    THEN
      PERFORM public.log_fraud_event(
        auth.uid(), v_machine.gym_id, 'ble_identity_post_connect_mismatch', 'high',
        jsonb_build_object(
          'machine_id', p_machine_id,
          'expected_name', v_machine.ble_device_name,
          'expected_serial', v_machine.ble_serial_number,
          'observed_name', p_observed_name,
          'observed_serial', p_observed_serial
        ));
      RETURN jsonb_build_object('verified', false, 'action', 'mismatch');
    END IF;
    RETURN jsonb_build_object('verified', true, 'action', 'already_verified');
  END IF;

  -- Backfill path: cache observed values
  UPDATE public.machines
  SET ble_device_name      = COALESCE(ble_device_name, p_observed_name),
      ble_serial_number    = COALESCE(ble_serial_number, p_observed_serial),
      ble_pairing_verified = (p_observed_serial IS NOT NULL),
      updated_at           = NOW()
  WHERE id = p_machine_id;

  v_action := CASE
    WHEN p_observed_serial IS NOT NULL THEN 'verified_and_cached'
    WHEN p_observed_name IS NOT NULL THEN 'name_cached_pending_serial'
    ELSE 'no_change'
  END;

  v_changes := jsonb_build_object(
    'cached_name', v_machine.ble_device_name IS NULL AND p_observed_name IS NOT NULL,
    'cached_serial', v_machine.ble_serial_number IS NULL AND p_observed_serial IS NOT NULL,
    'verified', p_observed_serial IS NOT NULL
  );

  RETURN jsonb_build_object('verified', true, 'action', v_action, 'changes', v_changes);
END;
$$;

GRANT EXECUTE ON FUNCTION public.cache_machine_ble_identity(UUID, TEXT, TEXT) TO authenticated;

COMMENT ON FUNCTION public.cache_machine_ble_identity(UUID, TEXT, TEXT) IS
  'Auto-backfill or verify BLE identity for a machine. Called by mobile client '
  'after successful BLE connection. First call caches observed name+serial and '
  'sets ble_pairing_verified=true. Subsequent calls verify match — mismatch '
  'logs ble_identity_post_connect_mismatch fraud event. Anti-spoofing: caller '
  'must hold the machine lock (current_user_id = auth.uid() AND is_busy=true).';
```

#### Subtask 2.2 — Read DIS Serial Number after GATT connect

After protocol detection (FTMS / CSC / Yesoul) succeeds and we have `server` connected, attempt to read DIS Serial Number. This is non-fatal — older non-FTMS-spec-compliant machines may not implement DIS, in which case we log a warning and skip serial.

Add helper function in `MachinesManager.tsx`:

```typescript
async function readDISSerialNumber(server: BluetoothRemoteGATTServer): Promise<string | null> {
  try {
    const disService = await server.getPrimaryService('device_information');
    const serialChar = await disService.getCharacteristic('serial_number_string');
    const valueDataView = await serialChar.readValue();
    const decoder = new TextDecoder('utf-8');
    const serial = decoder.decode(valueDataView).trim();
    return serial.length > 0 ? serial : null;
  } catch (err) {
    console.warn('[Pairing] DIS Serial Number not available:', err);
    return null;  // non-FTMS machines may not implement DIS
  }
}
```

```typescript
export interface MachineIdentity {
  id: string;                              // machine UUID (DB)
  ble_device_name: string | null;          // PRIMARY identifier
  ble_serial_number: string | null;        // SECONDARY verifier (post-connect)
  ble_pairing_verified: boolean;           // strict verification required if true
  sensor_id: string | null;                // legacy, fallback ONLY for unpaired machines
  ble_protocol?: 'ftms' | 'csc' | 'yesoul' | null;
}

async connectToMachine(machine: MachineIdentity): Promise<boolean> {
  // 1. Determine identity strategy
  // 2. Scan for peripherals
  // 3. Filter scan results by name match
  // 4. If no match: throw BlePeripheralNotFoundError
  // 5. If multiple matches: throw BleAmbiguousIdentityError
  // 6. Connect to the unique match
  // 7. Read DIS Serial Number
  // 8. Verify or auto-backfill
}
```

#### Subtask 3.2 — Identity strategy decision tree

```typescript
type IdentityStrategy =
  | { kind: 'name'; expectedName: string }                      // primary path
  | { kind: 'name+serial'; expectedName: string; expectedSerial: string }  // strict
  | { kind: 'legacy_strongest_rssi_with_warning' };             // fallback for unmigrated machines

function deriveIdentityStrategy(machine: MachineIdentity): IdentityStrategy {
  if (machine.ble_pairing_verified && machine.ble_device_name && machine.ble_serial_number) {
    return { kind: 'name+serial', expectedName: machine.ble_device_name, expectedSerial: machine.ble_serial_number };
  }
  if (machine.ble_device_name) {
    return { kind: 'name', expectedName: machine.ble_device_name };
  }
  // Legacy unpaired machine — no name on file. We MUST refuse this in production
  // OR pick strongest with explicit Sentry warning. For pilot rollout:
  log.warn('[BLE] Machine has no ble_device_name — strongest-RSSI fallback ENABLED. Auto-backfill on connect.');
  Sentry.captureMessage('ble.legacy_strongest_rssi_fallback', {
    extra: { machine_id: machine.id, has_sensor_id: !!machine.sensor_id },
    level: 'warning',
  });
  return { kind: 'legacy_strongest_rssi_with_warning' };
}
```

The legacy fallback is **temporary** — once admin operator backfills `ble_device_name` for all machines (or auto-backfill via Step 1's `cache_machine_ble_identity` RPC fires for each machine on first workout), this branch is never hit. After 7 days of pilot operation with zero `ble.legacy_strongest_rssi_fallback` events, this branch can be removed in a future build (`legacy_strongest_rssi_fallback_removed`).

#### Subtask 3.3 — Scan + filter by name

```typescript
async connectToMachine(machine: MachineIdentity): Promise<boolean> {
  const strategy = deriveIdentityStrategy(machine);

  // Simulator and Yesoul-by-direct-id paths short-circuit (existing logic)
  if (machine.sensor_id?.startsWith('sim:')) {
    return this.connectSimulator(machine.sensor_id);
  }

  log.debug('[BLE] connectToMachine', { machineId: machine.id, strategy: strategy.kind });
  this.emitStatus('Scanning...');

  if (Platform.OS === 'android') {
    await this.requestAndroidPermissions();
  }

  const devices = await this.scanForDevices(5000);
  if (devices.length === 0) {
    throw new BlePeripheralNotFoundError(
      machine.ble_device_name ?? machine.sensor_id ?? '(unknown)',
      'No BLE devices in range',
    );
  }

  let targetDevice: BLEDevice;

  switch (strategy.kind) {
    case 'name':
    case 'name+serial': {
      const matches = devices.filter(d => d.name === strategy.expectedName);
      if (matches.length === 0) {
        log.warn('[BLE] Expected name not found in scan', {
          expectedName: strategy.expectedName,
          discovered: devices.map(d => ({ name: d.name, id: d.id, rssi: d.rssi })),
        });
        throw new BlePeripheralNotFoundError(
          strategy.expectedName,
          `Machine not in range. Scanned ${devices.length} devices, none matched.`,
        );
      }
      if (matches.length > 1) {
        log.error('[BLE] Multiple peripherals broadcasting same name — factory defect or impostor', {
          name: strategy.expectedName,
          matches: matches.map(m => ({ id: m.id, rssi: m.rssi })),
        });
        Sentry.captureMessage('ble.duplicate_name_in_scan', {
          extra: { name: strategy.expectedName, matches },
          level: 'error',
        });
        throw new BleAmbiguousIdentityError(strategy.expectedName);
      }
      targetDevice = matches[0];
      break;
    }
    case 'legacy_strongest_rssi_with_warning': {
      targetDevice = devices.sort((a, b) => (b.rssi ?? -100) - (a.rssi ?? -100))[0];
      break;
    }
  }

  log.debug('[BLE] Connecting to matched peripheral', {
    name: targetDevice.name, id: targetDevice.id, rssi: targetDevice.rssi,
  });
  this.emitStatus(`Connecting: ${targetDevice.name ?? 'device'}`);

  // Existing protocol detection + connect logic
  const connected = await this.connectToDeviceById(targetDevice.id);
  if (!connected) {
    throw new Error('Connection returned false');
  }

  // Capture observed identity
  this.verifiedDeviceName = targetDevice.name ?? null;

  // Read DIS Serial Number for auto-backfill or verification
  const observedSerial = await this.readDeviceInformationServiceSerial();
  this.verifiedSerialNumber = observedSerial;

  // Belt-and-suspenders: if we expected a specific serial, verify it
  if (strategy.kind === 'name+serial') {
    if (observedSerial === null) {
      log.warn('[BLE] Expected verified serial but DIS read returned null. Disconnect for safety.');
      await this.disconnect();
      throw new BlePeripheralMismatchError(
        `Expected serial ${strategy.expectedSerial}, but DIS Serial Number characteristic could not be read.`,
      );
    }
    if (observedSerial !== strategy.expectedSerial) {
      log.error('[BLE] DIS Serial Number mismatch — connected to wrong physical machine!', {
        expectedSerial: strategy.expectedSerial,
        observedSerial,
      });
      await this.disconnect();
      throw new BlePeripheralMismatchError(
        `Connected machine reports serial ${observedSerial}, expected ${strategy.expectedSerial}.`,
      );
    }
    log.debug('[BLE] Serial verification passed', { serial: observedSerial });
  }

  // Async: cache observed identity to DB (auto-backfill or verify)
  // Don't await — non-blocking, fail-soft
  void this.cacheBleIdentityToBackend(machine.id, this.verifiedDeviceName, observedSerial);

  return true;
}
```

```typescript
private async readDeviceInformationServiceSerial(): Promise<string | null> {
  try {
    if (Platform.OS === 'ios') {
      if (!this.device || !(this.device as Device).readCharacteristicForService) return null;
      const valueBase64 = await (this.device as Device).readCharacteristicForService(
        DIS_SERVICE_UUID,
        DIS_SERIAL_NUMBER_CHAR_UUID,
      );
      return decodeBase64ToUtf8(valueBase64.value).trim() || null;
    } else if (Platform.OS === 'android') {
      if (!this.deviceId) return null;
      const valueBytes: number[] = await BleManager.read(
        this.deviceId,
        DIS_SERVICE_UUID,
        DIS_SERIAL_NUMBER_CHAR_UUID,
      );
      return new TextDecoder('utf-8').decode(new Uint8Array(valueBytes)).trim() || null;
    }
    return null;
  } catch (err) {
    log.debug('[BLE] DIS Serial Number not readable (non-FTMS or pre-FTMS firmware):', err);
    return null;
  }
}

private async cacheBleIdentityToBackend(
  machineId: string,
  observedName: string | null,
  observedSerial: string | null,

      log.warn('[BLE] cache_machine_ble_identity RPC error (non-fatal):', error);

  } catch (err) {
    log.warn('[BLE] cache_machine_ble_identity threw (non-fatal):', err);
  }
}
```

#### New helper: `ble_identity_matches_machine`

```sql
CREATE OR REPLACE FUNCTION public.ble_identity_matches_machine(
  p_observed_name   TEXT,
  p_observed_serial TEXT,
  p_expected_name   TEXT,
  p_expected_serial TEXT,
  p_pairing_verified BOOLEAN
)
RETURNS BOOLEAN
LANGUAGE plpgsql
IMMUTABLE
SET search_path = public
AS $$
BEGIN
  -- Backward compat: client didn't send observation → fail open
  IF p_observed_name IS NULL AND p_observed_serial IS NULL THEN
    RETURN TRUE;
  END IF;

  -- Strict mode: pairing was verified post-connect with serial
  IF p_pairing_verified AND p_expected_serial IS NOT NULL THEN
    -- Serial is hardware-bound truth; if observed and present, it must match
    IF p_observed_serial IS NOT NULL THEN
      RETURN p_observed_serial = p_expected_serial;
    END IF;
    -- No observed serial but verified pairing exists: trust observed name (DIS may have failed transiently)
    IF p_observed_name IS NOT NULL AND p_expected_name IS NOT NULL THEN
      RETURN p_observed_name = p_expected_name;
    END IF;
    RETURN FALSE; -- no observation means we can't verify
  END IF;

  -- Loose mode: only name on file (legacy / pre-verified machine)
  IF p_expected_name IS NOT NULL THEN
    IF p_observed_name IS NOT NULL THEN
      RETURN p_observed_name = p_expected_name;
    END IF;
    -- No observed name but expected name exists: can't verify, fail closed
    RETURN FALSE;
  END IF;

  -- Legacy machine with no ble_device_name: fail open (will be auto-backfilled by client)
  RETURN TRUE;
END;
$$;
```

#### Updated `update_machine_heartbeat`

```sql
CREATE OR REPLACE FUNCTION public.update_machine_heartbeat(
  p_machine_id      UUID,
  p_user_id         UUID,
  p_observed_name   TEXT DEFAULT NULL,
  p_observed_serial TEXT DEFAULT NULL
)
RETURNS BOOLEAN
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  v_gym_id           UUID;
  v_expected_name    TEXT;
  v_expected_serial  TEXT;
  v_pairing_verified BOOLEAN;
  v_session_id       UUID;
BEGIN
  SELECT gym_id, ble_device_name, ble_serial_number, ble_pairing_verified
  INTO v_gym_id, v_expected_name, v_expected_serial, v_pairing_verified
  FROM public.machines
  WHERE id = p_machine_id;

  IF auth.uid() IS NULL OR auth.uid() <> p_user_id THEN
    PERFORM public.log_fraud_event(auth.uid(), v_gym_id, 'heartbeat_unauthorized', 'high',
      jsonb_build_object('machine_id', p_machine_id, 'requested_user_id', p_user_id));
    RAISE EXCEPTION 'Unauthorized';
  END IF;

  -- BLE identity check
  IF NOT public.ble_identity_matches_machine(
    p_observed_name, p_observed_serial,
    v_expected_name, v_expected_serial, v_pairing_verified
  ) THEN
    PERFORM public.log_fraud_event(
      p_user_id, v_gym_id, 'ble_identity_server_mismatch', 'high',
      jsonb_build_object(
        'machine_id', p_machine_id,
        'check', 'heartbeat',
        'expected_name', v_expected_name,
        'expected_serial', v_expected_serial,
        'observed_name', p_observed_name,
        'observed_serial', p_observed_serial,
        'pairing_verified', v_pairing_verified
      ));

    -- Mark active session as compromised
    SELECT id INTO v_session_id
    FROM public.sessions
    WHERE user_id = p_user_id AND machine_id = p_machine_id AND is_active = true
    ORDER BY started_at DESC LIMIT 1;

    IF v_session_id IS NOT NULL THEN
      UPDATE public.sessions
      SET raw_metrics = jsonb_set(
        COALESCE(raw_metrics, '{}'::jsonb),
        '{security,ble_identity_mismatch}',
        '"true"'::jsonb,
        true
      )
      WHERE id = v_session_id;
    END IF;

    RETURN FALSE;
  END IF;

  -- Existing heartbeat update
  UPDATE public.machines
  SET last_heartbeat = NOW()
  WHERE id = p_machine_id AND current_user_id = p_user_id AND is_busy = true;

  IF NOT FOUND THEN
    PERFORM public.log_fraud_event(p_user_id, v_gym_id, 'heartbeat_without_lock', 'medium',
      jsonb_build_object('machine_id', p_machine_id));
  END IF;

  RETURN FOUND;
END;
$$;
```

## API Contracts

### `cache_machine_ble_identity(p_machine_id, p_observed_name, p_observed_serial)` (NEW RPC, Step 1)
Returns: `JSONB { verified: boolean, action: 'no_change'|'name_cached_pending_serial'|'verified_and_cached'|'already_verified'|'mismatch', changes?: object }`

Auth: requires `auth.uid() = machines.current_user_id AND machines.is_busy = true`. Otherwise throws.

Idempotent: subsequent calls are no-ops if values already cached. Mismatch on already-verified machine logs fraud event, returns `{verified:false, action:'mismatch'}`.

### `update_machine_heartbeat` (UPDATED, Step 5)
**Old signature:** `(p_machine_id UUID, p_user_id UUID) → BOOLEAN`
**New signature:** `(p_machine_id UUID, p_user_id UUID, p_observed_name TEXT DEFAULT NULL, p_observed_serial TEXT DEFAULT NULL) → BOOLEAN`

Backward compat: NULL observed values fail-open (existing mobile clients work unchanged).

### `update_machine_rpm` (UPDATED, Step 5)
**Old signature:** `(p_machine_id UUID, p_user_id UUID, p_rpm INTEGER) → BOOLEAN`
**New signature:** `(p_machine_id UUID, p_user_id UUID, p_rpm INTEGER, p_observed_name TEXT DEFAULT NULL, p_observed_serial TEXT DEFAULT NULL) → BOOLEAN`

### `award_drops(p_session_id UUID)` (UPDATED, Step 5 — signature unchanged)
New early-exit branch: if `sessions.raw_metrics.security.ble_identity_mismatch = 'true'`, returns `(0, 1.0, [])` and logs fraud event. Function signature unchanged — purely additive logic.

### `bleService.connectToMachine(machine: MachineIdentity): Promise<boolean>` (NEW client method, Step 3)
Replaces `connectToDevice(sensorId)` for all paired-machine paths. Throws `BlePeripheralNotFoundError`, `BleAmbiguousIdentityError`, `BlePeripheralMismatchError` per failure mode.

## Risk Register

| # | Risk | Mitigation |
|---|---|---|
| R1 | Some FTMS machines don't expose DIS Serial Number | Strategy `'name'` (without serial) is supported; `ble_pairing_verified` stays false; matching falls back to name-only. Logged but not blocking. |
| R2 | Two real machines factory-burned with same Local Name | `BleAmbiguousIdentityError` blocks workout; unique trigger blocks pairing; ops contact vendor. Defensive but expected to be rare. |
| R3 | Legacy machine without ble_device_name + multiple FTMS in scan range | Strongest-RSSI fallback fires once + auto-backfill via `cache_machine_ble_identity`. Cross-talk possible for ONE workout per machine, then strict matching activates. Acceptable transition cost. |
| R4 | iOS DIS read latency (~200-400ms) adds to connect time | Acceptable for one-time post-connect verification. Not in hot path. |
| R5 | Older mobile builds (without observed_*) deployed alongside Step 5 backend | Backward compat fail-open: NULL observed values pass `ble_identity_matches_machine` → no impact. Step 5 deploys safely independent of mobile timing. |
| R6 | Operator re-pairs all 9 Vortex machines but pilot users still have old broken build | Step 4 mobile build is the fix; this plan's critical path delivers that within 24h. Phase E gates wider distribution on Sentry health. |
| R7 | Trigger `trg_machines_ble_device_name_unique` blocks legitimate update during gym migration (e.g., moving machine from gym A to gym B) | Trigger checks per-(gym_id, ble_device_name); cross-gym moves are unaffected. Within-gym duplicate is a real conflict and SHOULD block. |
| R8 | DIS Serial read returns trimmed-empty string on some firmwares | `readDISSerialNumber` returns null on empty after trim; treated as serial-not-available; falls back to name-only matching. |
| R9 | Auto-backfill RPC race condition: two phones connect to same legacy machine simultaneously | RPC uses `FOR UPDATE` row lock; first writer wins; second sees `ble_pairing_verified=true` and goes verify path. Idempotent. |
| R10 | Mobile build 22 ships before admin operator re-pairs Vortex machines | Legacy fallback (strongest-RSSI + auto-backfill) handles this. First workout per machine still works (with cross-talk possible for that one session). After auto-backfill, strict matching takes over. Phase B has operator re-pair BEFORE Phase C ships → no users hit legacy fallback at all. |
